## 1. 使用边界与证据状态

本策略库累计参考 90 张有效横版咨询页面记录：上一轮 12 张，本轮从 14 篇 Obsidian Markdown 的 127 个唯一图片链接中确认 78 张有效内容页。本轮包括 38 张深蓝／灰／红咨询页和 40 张青蓝研究报告页。两个视觉家族仍属于同一发布生态，因此只能提高候选规则的样本覆盖，不能证明跨机构普适性。本轮未重新取得上一轮原始清单做跨轮哈希去重，所以 90 只能理解为两轮有效记录相加。截图主要约为 1080 × 602 或 1080 × 608 像素，只支持相对比例、模块数量和重复构图观察，不能证明原始 PPT 坐标、字号、母版设置或业务效果。

始终遵守以下优先级：

1. 客户 PPTX 的母版、版式、字体、色彩、页边距、页眉页脚、Logo 和页码；
2. 页面要支持的决策与单一沟通任务；
3. 内容完整性、证据强度与日文可读性；
4. 本策略库中的空间比例和构图建议。

不得从参考样本复制机构标识、原文、数据、Logo、装饰性签名、截图或高度可识别的视觉资产。只借鉴信息层级、空间组织和视觉叙事。

### 证据等级

| 等级 | 定义 | 使用方式 |
| --- | --- | --- |
| 推荐规则 | 至少 3 个独立设计家族共同支持 | 可作为默认起点，仍服从客户模板 |
| 候选规则 | 当前样本中反复出现，但仍属于同一设计家族 | 可选用，不得宣称为普遍最佳实践 |
| 灵感 | 仅 1 张有效页面支持 | 只在内容结构高度匹配时使用 |
| 专业回退 | 不是从当前样本推导，而是为证据缺口设置的保守护栏 | 必须标注为非样本规则 |

当前版本没有任何“推荐规则”。重复出现的规律最多为“候选规则”，需要未来用至少第三个独立设计家族或真实客户模板继续验证。青蓝研究报告页的高密度只作为留存阅读条件证据，不可反向证明会议投影页应使用小字号或高密度。

## 2. 版式选择流程

在绘制 SVG 前完成以下步骤：

1. 用一句话写出页面任务：`观众看完后应理解／相信／选择／批准什么`。
2. 先确定输出模式：`projected presentation`（会议投影）或 `leave-behind report`（留存阅读）。
3. 按沟通任务分类，不按行业名词分类。
4. 只选一个主版式；其他内容只能作为次级证据，不能再形成第二套并列叙事。
5. 从客户模板读取正文安全区，记为宽度 `Bw`、高度 `Bh`。
6. 将本文件的百分比换算到 `Bw × Bh`，不得直接套用截图坐标。
7. 写入页面清单：输出模式、版式 ID、模块数、宽度分配、密度等级、证据等级、日文扩容预留。
8. 如果内容超载，依次采用：删减非决策信息 → 合并重复信息 → 改用更合适版式 → 拆页。最后才考虑缩小文字。

### 快速选择

| 页面任务 | 优先版式 |
| --- | --- |
| 解释商业机制、能力链或驱动因素 | `MECH-3`、`MOAT-3` |
| 汇总经营表现、关键指标或阶段变化 | `KPI-3` |
| 说明飞轮、壁垒和支撑证据 | `FLYWHEEL-2` |
| 比较竞品、替代方案或相对定位 | `COMPARE-3`、`MATRIX-3` |
| 展开客户价值主张 | `VALUE-4` |
| 解释双重收入来源或双引擎模式 | `REVENUE-2` |
| 展示获客、转化、留存等顺序关系 | `PROCESS-3` |
| 展示公司演进、产品体系和战略取舍 | `CASE-TIMELINE` |
| 展示全球网络、生态角色与供给规模 | `NETWORK-3` |
| 展示渠道政策、服务体系与经营限制 | `OPS-3` |
| 汇总 4–6 组并列证据、发现或能力 | `EVIDENCE-GRID` |
| 展示 4–6 个连续步骤或双泳道流程 | `PROCESS-LINE` |
| 用一个主图表回答结论并解释原因 | `CHART-INSIGHT` |
| 展示产品、部件或技术依赖层级 | `LAYERED-STACK` |

可叠加以下模块，但不得把模块 ID 当作第二套主版式：

- `MOD-INSIGHT-RAIL`：左／右侧洞察栏。
- `MOD-IMPLICATION-BAND`：仅在承载正文未表达的关键含义时使用的底部结论、含义或假设带；不是默认收尾组件。

## 3. 全局量化护栏

以下为截图视觉估算值。应用时以客户模板安全区为基准重新校准。

### 3.1 页面分区

| 项目 | 当前样本观察 | 候选护栏 |
| --- | --- | --- |
| 左右外边距 | 约占整页宽度 3%–5% | 使用模板既有边距；没有定义时从 4% 起步 |
| 标题顶部位置 | 约占整页高度 4%–8% | 标题不得侵入母版家具；一行优先 |
| 标题与副标题区 | 约占整页高度 17%–26% | 正文通常从整页高度 21%–27% 处开始 |
| 正文有效宽度 | 约占整页宽度 90%–94% | 不越过模板安全区 |
| 来源／注释区 | 约占整页高度 3%–6% | 必须可见，不能依靠演讲者备注替代页面必要来源 |
| 正文模块数 | 2–4 个一级模块 | 3 个最常见；超过 4 个时改用表格、矩阵或拆页 |
| 一级模块间距 | 约占正文宽度 1.3%–2.8% | 三栏从 2% 起步；四栏从 1.2%–1.6% 起步 |
| 正文留白 | 约占正文区域 10%–20% | 若低于约 8%，优先判定为内容过载 |

### 3.2 输出模式护栏

同一版式在不同输出模式下必须采用不同密度。不得以“报告页上存在”为理由，把留存阅读密度迁移到会议投影。

| 项目 | 会议投影 `projected` | 留存阅读 `leave-behind` |
| --- | --- | --- |
| 一级信息模块 | 2–4 个；6 个仅限极短证据卡 | 3–6 个；原生表格可达到 8 个结构块 |
| 正文留白 | 正文区建议不低于 12% | 正文区建议不低于 8% |
| 模块内信息点 | 每模块 2–4 个 | 每模块 3–5 个，且必须有扫描结构 |
| 阅读距离 | 必须通过整页投影尺寸检查 | 必须通过 100% 页面阅读检查 |
| 高密度表格 | 默认拆页或移至附录 | 可保留，但每格仍需清晰且可编辑 |
| 结论位置 | 优先融入标题、副标题或正文重点；底部含义带仅条件使用 | 标题、副标题、洞察栏或正文重点优先；底部含义带仅条件使用 |

如果输出模式未知，按会议投影的更严格护栏处理，并向用户确认用途。

### 3.3 字体层级

截图只能支持相对关系，不能反推出 PPT 点数。

| 层级 | 相对标题字号 | 候选护栏 |
| --- | --- | --- |
| 页面标题 | 100% | 一行优先；不得因超长标题压缩整页正文 |
| 页面副标题／结论解释 | 55%–68% | 1–2 行；与标题形成清晰间隔 |
| 模块标题 | 58%–75% | 同层级必须等大；深色标题条内保持高对比 |
| 正文 | 45%–58% | 同页最多两档正文大小 |
| 来源与注释 | 28%–38% | 不得低于客户模板允许的最小字号 |

### 3.4 颜色与强调

- 使用一种深色承担标题、结构和主要关系；使用中性灰承载背景和次要信息。
- 每页只允许一种高警示强调色承担关键数字、风险、反例或结论，不得同时承担装饰功能。
- 单页高警示色面积通常控制在正文可视面积的 3%–8%；超过约 10% 时会削弱优先级。
- 图标只承担分类、对象或动作提示。删除图标后若逻辑不受影响且页面更清晰，应删除图标。

### 3.5 内容密度

将页面密度标为以下一种：

| 密度 | 适用情况 | 模块级护栏 |
| --- | --- | --- |
| 低 | 封面、章节、单一关键结论 | 1–2 个模块；正文不超过 3 个短句 |
| 中 | 机制、流程、价值主张、案例概览 | 2–4 个模块；每模块 3–5 个信息点 |
| 高 | 留存阅读报告、竞争矩阵、经营体系、尽调型案例页 | 必须标记 `leave-behind` 或附录；使用表格／矩阵结构；每格最多 2–3 行；另设结论或风险栏 |

不得用大量独立文本框模拟表格。存在稳定行列关系时使用原生 PowerPoint 表格。

### 3.6 常用模块量化标准

| 模块 | 候选比例 | 执行边界 |
| --- | --- | --- |
| `MOD-INSIGHT-RAIL` | 洞察栏约 `16%–22% Bw`；主内容约 `74%–80% Bw`；间距 `2%–4% Bw` | 洞察栏只放 1 个主结论或 2–3 个短洞察，不另起完整叙事 |
| `MOD-IMPLICATION-BAND` | 底部约 `6%–10% Bh` | 非默认模块；仅承载正文未表达的决策含义、风险、假设或下一步。投影页最多 1 个结论、2 行；留存页最多 3 个短要点 |
| 卡片网格间距 | 横向 `1.4%–2.2% Bw`；纵向 `2%–4% Bh` | 不通过压缩间距容纳长文；优先删减或拆页 |
| 图表与洞察栏 | 图表 `65%–75% Bw`；洞察栏 `20%–30% Bw` | 图表必须支持标题结论；洞察栏不复述所有数据点 |

## 4. 日文商务材料容量护栏

以下属于专业回退，并非从中文截图直接验证。最终仍需用实际日文在客户字体中做 SVG 和 PowerPoint 适配检查。

- 当中文内容将在后续翻译为日文时，为正文文本框预留约 15%–25% 的额外容量；专业术语、敬语和括号说明较多时取高值。
- 页面标题以 18–34 个日文全角字符为一行目标。超过约 34 个字符时先重写标题；只有客户模板明确允许时才改为两行。
- 副标题以 35–60 个日文全角字符为目标，最多两行。
- 会议投影三栏页面每栏以 2–4 个要点为宜，每个要点约 15–28 个日文全角字符；留存阅读可增加至 3–5 个，但必须在生产字体中复核。
- 会议投影四栏页面每栏以 2–3 个要点为宜，每栏正文总量以约 36–60 个日文全角字符为起点；超出时优先拆页。
- 矩阵单元格以 12–28 个日文全角字符、最多 3 行作为起点。超过后改写维度或拆页。
- 2×3 证据网格的投影页，每卡以 1 个小结论加 1–2 条证据为起点；留存阅读每卡最多 3–4 条短证据。
- 禁止通过减少栏间距、压缩行距或使用中文字体容纳日文。先缩短文案、增加模块高度或拆页。

## 5. 页面类型策略

### `MECH-3`：三栏机制拆解

适用：同时解释商业模式、产品／能力和技术／组织支撑。

- 证据：S002、S014、A020、A030、A061；跨多个主题重复出现，但主要来自同一发布生态。
- 等级：候选规则。
- 正文分为 3 栏，每栏宽度约为 `31%–32% Bw`，栏间距约为 `2% Bw`。
- 每栏使用一个明确问题，例如“价值如何产生”“由什么能力支撑”“结果如何形成”。
- 每栏最多 2 个层级：上部机制图，下部证据／结果；禁止在每栏再嵌套 3 个以上子框架。
- 模块标题条约占模块高度的 8%–12%。
- 每栏以 3–5 个一级节点为宜；箭头只表达单向因果或输入输出。

### `KPI-3`：三栏经营表现与阶段变化

适用：把历史基准、当前经营数据和资本／阶段变化放在一页。

- 证据：S003。A022 是 2×2 KPI 证据网格，不能直接作为三栏结构证据。
- 等级：灵感。
- 三栏各占约 `30%–32% Bw`，中间使用轻分隔，不使用厚重边框。
- 每栏承载 4–6 个 KPI；每个 KPI 只保留名称、数值、方向和必要基期。
- 同一栏中只允许一个主要图形语法，例如迷你柱图、KPI 卡或时间轴。
- 负面或未转正指标使用唯一警示色；不得把所有增长数字都着色。
- 估值、融资等不可直接相加的信息应使用时间线或事件框，而不是堆入 KPI 列表。

### `FLYWHEEL-2`：飞轮、核心壁垒与双证据底座

适用：说明增长循环如何由两组运营能力支撑。

- 证据：S004。A050 是围绕中心对象的能力网络，不具备可验证的循环因果，因此不计入飞轮证据。
- 等级：灵感。
- 上部主飞轮占 `42%–50% Bh`；中心只放一个循环结论。
- 飞轮下设置一条 `5%–8% Bh` 的“核心壁垒”承重条，把上层循环与下层证据连接起来。
- 下部使用 2 个等宽证据面板，各占约 `48%–49% Bw`。
- 飞轮节点控制在 3–5 个；若超过 5 个，改用流程或生态图。
- 下部证据必须能验证上部循环，不得只是补充信息。

### `COMPARE-3`：比较表、量化图和解释栏

适用：同时回答“谁不同”“差多少”“为什么难复制”。

- 证据：S005、A018、A023、A039、A049、A073、A093、A095、A100、A102、A104、A112。
- 等级：候选规则。
- 推荐宽度起点：比较表 `43%–46% Bw`，量化图 `26%–30% Bw`，解释栏 `25%–28% Bw`。
- 比较表控制在 3–5 个对象、2–4 个比较维度。
- 图表只承载一个量化关系；解释栏只保留表层策略与深层能力的区分。
- 解释栏可使用上下两个强弱对比卡，但只有一个结论卡使用深色底。
- 表格、图表和解释必须共享同一比较口径，不能分别回答三个无关问题。

### `NETWORK-3`：定位、网络与供给规模

适用：解释平台、供应链或生态系统的角色和覆盖范围。

- 证据：S007、A015、A040、A050、A082、A103、A120。
- 等级：候选规则。
- 左侧定位栏约 `24%–28% Bw`，中心网络视觉约 `45%–50% Bw`，右侧规模栏约 `23%–27% Bw`。
- 中心地图或网络图必须是主视觉；底图降低对比度，节点和路径承担叙事。
- 地图节点以 3–6 个为宜；超过后改用分区地图或表格。
- 左栏回答“是谁、服务谁、如何交易”；右栏回答“规模多大、供给什么”。
- 不得用地图暗示未被数据验证的覆盖或市场份额。

### `VALUE-4`：四维价值主张卡片

适用：拆解 4 个并列、相互独立的客户价值。

- 证据：S008、A027、A124。
- 等级：候选规则。
- 四栏各占 `23%–24% Bw`，栏间距约 `1.2%–1.6% Bw`。
- 每栏结构固定为：图标区 `18%–24%`、价值标题 `12%–18%`、证据区 `55%–65%`。
- 每栏 2–3 个要点；四栏的句法、长度和证据粒度保持平行。
- 四个价值必须 MECE。若出现因果从属关系，改用机制或流程版式。
- 图标必须同一线性风格，大小误差控制在约 10% 内。

### `REVENUE-2`：双引擎收入／盈利模式

适用：解释两类相互补充的收入来源及其连接关系。

- 证据：S009。
- 等级：灵感。
- 左右两区各占约 `47%–48% Bw`，中间关系区约 `4%–6% Bw`。
- 单侧最多展示 3 个层级／套餐；高低差异使用高度、位置或标签中的一种，避免重复编码。
- 中心只保留一个桥接命题，例如“复合收入模式”。
- 全页只设一个高警示色结论框，用于最关键利润机制或商业限制。
- 若两种收入来源没有逻辑连接，应拆成两页而不是强行使用双引擎。

### `PROCESS-3`：三阶段获客、转化与锁定

适用：展示具有明确顺序、输入输出和阶段目标的流程。

- 证据：S010、A016、A029、A051、A116、A118、A125。A069 属于六步双泳道，应归入 `PROCESS-LINE`。
- 等级：候选规则。
- 三个步骤卡各占 `29%–31% Bw`，步骤间箭头／连接区约 `3%–5% Bw`。
- 每卡使用统一结构：阶段标题、一个核心图标、2–4 个动作、一个结果框。
- 箭头只表达阶段前后关系，不承载文字。
- 阶段标题使用编号和动词；三个阶段必须处于同一抽象层级。
- 若存在循环回流，使用飞轮；若步骤超过 5 个，使用横向时间轴或泳道图。

### `CASE-TIMELINE`：公司演进、产品体系与战略取舍

适用：案例页中同时展示历史节点、当前产品结构和战略判断。

- 证据：S013、A006、A025、A033、A078。
- 等级：候选规则。
- 顶部时间轴占 `18%–23% Bh`，控制在 3–5 个关键节点。
- 下部占 `67%–72% Bh`，分为约 `51%–54% Bw` 的产品／业务结构和 `44%–47% Bw` 的战略判断／市场说明。
- 时间轴只保留改变战略方向的事件，不记录一般性年份。
- 产品层级使用堆叠、阶梯或金字塔，但每层只能表达一个主差异。
- 右下的市场数字必须说明统计口径和局限，不得为填满版面而加入弱相关规模数据。

### `MOAT-3`：三支柱汇聚至核心壁垒

适用：说明技术连续性、生态兼容和渠道合作如何共同形成迁移成本等壁垒。

- 证据：S014、A110；结构思想与 S002、S004、A015 互相支持。A061 是三栏机制，不计为汇聚型壁垒图。
- 等级：候选规则。
- 三个上层能力模块横向分布，宽度起点约为 `24% / 34% / 24% Bw`，其余为间距与连接空间。
- 所有连接线在底部汇聚到一个核心壁垒；汇聚结论只能有一个。
- 每个支柱最多 2–4 个能力节点，中央支柱可以比两侧多一个层级。
- 连接箭头旁只放结果词组，例如“降低成本”“提高收入”“增加切换损失”。
- 若三支柱彼此没有共同结果，改用并列价值主张而不是壁垒图。

### `OPS-3`：渠道政策、服务体系与经营限制

适用：展示一个 B2B 渠道体系如何通过政策、服务和触达方式驱动增长，同时揭示数据缺口。

- 证据：S015。
- 等级：灵感。
- 三栏宽度起点约为 `38%–40% / 28%–30% / 30%–32% Bw`。
- 左栏适合原生表格和规则卡；中栏适合线上／线下两个运营模块；右栏适合渠道事实和限制／风险。
- 每栏最多 3 个二级模块；二级模块标题必须能独立说明其作用。
- 风险与公开数据缺口集中放在一个警示模块，不与正常运营事实混排。
- 表格中的梯度、门槛和支付条件应保持可编辑，且逐项核对单位与时间。

### `MATRIX-3`：量化信号、竞争矩阵与风险栏

适用：同时展示市场压力的量化信号、竞品逐项比较和中长期风险。

- 证据：S016、A023、A037、A052、A068、A072、A079、A109。A013 是证据卡网格，不计为比较矩阵。
- 等级：候选规则。
- 左侧量化证据约 `18%–22% Bw`，中部矩阵约 `52%–58% Bw`，右侧风险栏约 `22%–26% Bw`。
- 矩阵控制在 4–6 个竞品和 3–5 个比较维度。
- 每个单元格最多 2–3 行；对本公司的直接威胁统一放在最后一列并使用警示色。
- 左侧图表最多 2 个，必须共用同一时间或市场逻辑。
- 右侧风险控制在 2–4 项，每项包含风险名称、机制和影响，不得只列名词。

### `EVIDENCE-GRID`：4–6 个证据模块网格

适用：汇总并列发现、能力、趋势、案例证据或验证条件，强调快速扫描和证据完整性。

- 证据：A007、A013、A021、A022、A038、A056、A059、A070、A071、A081、A085、A087、A089、A092、A097、A122。
- 等级：候选规则。
- 优先使用 2×2、1×4 或 2×3 网格；会议投影最多 6 卡，留存阅读可保留 6 卡但不得再嵌套小网格。
- 2×3 网格单卡宽度约 `31%–32% Bw`，横向间距 `1.4%–2.2% Bw`，纵向间距 `2%–4% Bh`。
- 卡片标题条约占卡高 `9%–14%`；标题句法保持平行。
- 投影页每卡只放 1 个小结论加 1–2 条证据；留存阅读每卡最多 3–4 条短证据。
- 若证据之间存在明确先后或因果，改用 `PROCESS-LINE` 或 `MECH-3`，不要伪装成并列卡片。

### `PROCESS-LINE`：4–6 步横向流程或双泳道

适用：展示超过三步的顺序关系、方法链、价值链、研发路径或两类对象的平行过程。

- 证据：A003、A005、A008、A041、A043、A046、A047、A048、A058、A067、A069、A127。
- 等级：候选规则。
- 单泳道控制在 4–6 步；每步约 `12%–18% Bw`，连接区约 `2%–4% Bw`。
- 每步只保留一个动词型标题、一个对象／动作和一个结果；连接线不承载长句。
- 双泳道时两条线必须共享阶段列；泳道标签约占 `9%–12% Bw`，最终共同结果区约占 `12%–18% Bw`。
- 流程下可叠加 `MOD-IMPLICATION-BAND`，但只解释反常识、风险或决策含义，不重复步骤。
- 超过 6 步时改用时间轴、泳道表或拆页；存在回流时改用飞轮。

### `CHART-INSIGHT`：主图表加集中洞察

适用：页面核心证据是一张或一组共享口径的图表，需要同时说明原因、假设、限制或决策含义。

- 证据：A034、A035、A042、A053、A054、A101、A115；跨两个视觉家族出现。
- 等级：候选规则。
- 图表区约占 `65%–75% Bw`，洞察栏约占 `20%–30% Bw`，间距约 `2%–4% Bw`。
- 两图并列时必须共享单位、时间或情景逻辑；单图表不要拆成多个装饰性小图。
- 洞察栏最多 3 项：结论、原因／机制、限制／下一步；不得逐点复述图表标签。
- 假设或口径较多且未被标题、副标题、洞察栏或图表注释充分表达时，可条件使用底部 `6%–10% Bh` 的 `MOD-IMPLICATION-BAND`；否则不要为了保护绘图区而机械增加底部横框。
- 图表必须使用原生 PowerPoint 图表和内嵌 Excel；截图只可作为独立参考图，不能冒充可编辑图表。

### `LAYERED-STACK`：技术、部件或产品层级栈

适用：解释技术架构、部件依赖、产品层次或从底层能力到上层体验的关系。

- 证据：A004、A044、A045；目前只在青蓝研究报告家族中重复出现。
- 等级：候选规则，但仅条件适用于技术说明或留存阅读。
- 主层级栈控制在 3–6 层，占 `35%–55% Bw`；解释区占 `40%–55% Bw`。
- 每层只写一个对象名称和一个作用，不得在层内塞入完整段落。
- 需要对比两套架构时，左右栈各占约 `42%–46% Bw`，中间关系区 `6%–10% Bw`。
- 会议投影必须简化为关键层和关键差异；完整技术细节放附录或留存阅读页。

### `MOD-INSIGHT-RAIL`：侧边洞察栏

适用：作为主版式的附加模块，用于先给判断、集中解释或承载限制。

- 证据：A036、A041、A068、A101、A102、A103、A104；左右两侧均有实例，较宽解释栏只在留存阅读页中使用。
- 等级：候选模块。
- 默认洞察栏约 `16%–22% Bw`，主区约 `74%–80% Bw`，中间留 `2%–4% Bw`；留存阅读可扩展到约 `22%–28% Bw`，但此时应减少主区复杂度。
- 洞察栏最多 1 个主结论或 2–3 个短洞察；如果需要完整证据链，改为独立页面。

### `MOD-IMPLICATION-BAND`：底部含义／结论带

适用：作为主版式的附加模块，把证据转成结论、风险、假设或下一步。

- 证据：A018、A049、A054、A069、A073、A102、A103、A104。
- 等级：候选模块。
- 高度约 `6%–10% Bh`；必须位于来源区上方，不能覆盖页脚或页码。
- 会议投影最多 1 个结论、2 行；留存阅读最多 3 个短要点。
- 结论带应回答“所以怎样”，不得只是重复页面标题或图表数值。
- 不得为了填满页面、制造完整感或形成统一模板而添加。若删除后页面的决策信息没有损失，应删除。
- 添加前必须确认其内容没有被标题、副标题、图表标注或正文表达，并且确有独立的决策价值。
- 优先考虑把结论自然融入结论型标题、副标题引导、正文内高亮或侧边洞察栏；但不得把所有底部结论框机械搬到副标题区。
- 连续页面不得无差别重复使用该模块。整套材料应根据页面任务灵活变化结论位置，避免模板感和审美疲劳。
- 来源注释、图例和客户模板规定的页脚属于功能性信息，不按总结模块处理。

## 6. 证据缺口与保守回退

以下页面类型没有有效样本直接支持，不得声称从当前样本学得：

| 页面类型 | 处理方式 |
| --- | --- |
| 正式封面 | 只使用客户模板；本轮头图样本已明确排除 |
| 议程／章节页 | 使用客户模板既有布局，不新增样本规则 |
| 执行摘要 | 可用 `SUMMARY-FALLBACK`，但必须标注为专业回退 |
| 图表洞察页 | 已有 `CHART-INSIGHT` 候选证据；纯满版图表仍按客户模板保守处理 |
| 组织架构页 | 保留证据缺口，除非用户提供样本 |
| 2×2 矩阵页 | 保留证据缺口，除非用户提供样本 |

### `SUMMARY-FALLBACK`：执行摘要保守回退

- 使用 3 个并列结论模块或 1 个总论点加 3 个证据模块。
- 每个模块只包含：一句结论、一个关键证据、一个决策含义。
- 全页一级信息不超过 5 个；不把目录或研究过程当作结论。
- 标记为“专业回退，非样本推导”。

## 7. 对抗式检查

在提交 SVG 审批前逐项反问：

- 如果删除颜色和图标，信息层级是否仍然成立？
- 页面是在解释一个结论，还是把多个分析硬塞在一起？
- 三栏或四栏是真的并列，还是隐藏了应当画成流程／因果的关系？
- 图表、表格和结论是否使用同一口径？
- 页面是否因为参考样本常用深蓝和灰色，就错误覆盖了客户模板色彩？
- 高警示色是否只标记最需要关注的信息？
- 日文翻译后是否仍有 15%–25% 容量，且没有依赖缩小字号？
- 是否已明确页面是会议投影还是留存阅读，并使用对应密度护栏？
- 是否把青蓝研究报告的小字号和高密度误当成投影页的正向规则？
- 是否把单一设计家族的惯例误写成普遍最佳实践？
- 是否存在比当前版式更简单、更直接的表达？
- 是否有任何事实、数字、来源或不确定性被版式隐藏？
- 底部是否出现了重复标题、正文或流程内容的总结框？删除后若不损失决策信息，应立即删除。
- 是否只是把底部总结框机械移到副标题区，而没有根据页面任务重新组织信息层级？
- 相邻页面是否重复同一种总结组件和位置，造成模板感或审美疲劳？
